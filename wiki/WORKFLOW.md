# 공통 제작 절차

목적은 같은 화면을 반복하는 것이 아니라, 전달하려는 내용을 이해한 뒤 적절한 표현을 고르는 것입니다. 짧은 작업은 한 번에 진행하고, 의미가 불분명한 부분만 질문합니다.

| 단계 | 실제로 하는 일 | 남기는 결과 |
|---|---|---|
| 1. 의도 확인 | 누구에게 무엇을 전달할지 정리. 경험·주장·홍보·설명 구분 | 핵심 메시지·범위 |
| 2. 레퍼런스 분석 | 장면·구도·전환·움직임·소리·자막을 시간과 함께 관찰 | 분석표, 프레임의 로컬 경로 |
| 3. 이야기 순서 | 배경→의도→시도→결과→배움 중 실제로 필요한 연결 배치 | 전체 대본과 의미상의 공백 |
| 4. 구어체 편집 | 반복 접속사와 긴 문장을 줄임. 사실·동기·인과는 보태지 않음 | 표시 대본, 필요한 발음용 문장 |
| 5. 장면 설계 | 문장별 핵심, 표정, 소품, 숫자, 등장·퇴장, 연결. 필요한 자산을 기존/변형/신규로 구분 | 문장→그림 대응표 + 자산 계획 |
| 6. 구현 선택 | 기존 방식 재사용/변형/새 방식 중 선택. 대표 장면으로 확인 | 방식 ID, 실제 구현 경로 |
| 7. 제작 | 자산과 모션 제작, 확정 문장으로 음성 준비. 실측 구간에 그림·자막 연결 | 편집 원본, 런타임, 자산, SRT |
| 8. 검토·출력 | 의미·타이밍·가독성·음성·수치·전체 디코딩 확인 | MP4, 검토 결과, 재출력 명령 |
| 9. 다음 작업 기록 | 재사용할 원칙과 이번 영상만의 결정을 구분 | 위키 사례 갱신, 다음 작업 프롬프트 |

## 대본에서 그림까지

전체 이야기를 먼저 검토합니다. 일부 30초를 시험할 경우에도 전체 대본에서 구간을 뽑고, 시험 구간을 전체 이야기로 착각하지 않습니다. 요청이 전체본으로 바뀌면 길이와 산출물 범위를 갱신합니다.

각 문장을 아래처럼 연결합니다. 텍스트 개수나 예쁜 소품보다 “이 그림이 왜 지금 필요한가”를 먼저 봅니다.

| 문장/구간 | 전달할 의미 | 화면의 주체·행동 | 소품·숫자 근거 | 등장·퇴장 | 불확실한 의미 |
|---|---|---|---|---|---|
| 장면 ID + 문장 번호 | 한 가지 중심 내용 | 누가 무엇을 하는가 | 실제/예시/개념 구분 | 어느 말에 들어오고 나가는가 | 질문 또는 없음 |

사용자 의도가 없으면 질문합니다. 예를 들어 “스티커 인쇄”가 실제 제공 기능인지 구체적 쓰임새의 예시인지에 따라 그림이 달라집니다. 문장 배치·표현·도형 위치처럼 되돌릴 수 있는 편집은 주어진 의도 안에서 진행합니다.

## 재사용과 검토

현재 Codex–Dot 협업에서는 Codex가 의도·대본·자산 요구를 정리하고 Dot이 구도·자산·모션을 제안/구현합니다. 전달 문서에 읽을 대본과 수정할 경로를 적어 같은 원본을 동시에 고치지 않습니다. 새 기획에 음성이 없으면 정지 시안부터 만들고, 임시 모션 시간을 실측 음성 정렬로 표현하지 않습니다. 확정 뒤 로컬에서 만든 TTS 구간으로 최종 그림·자막을 맞춥니다. 이 분담은 현재 환경의 선택입니다.

장면의 의미와 행동을 먼저 정한 뒤, 이를 표현할 캐릭터/포즈·소품·도해·풍선·이미지·동작을 적습니다. 현재 라이브러리에 있는 그림만 골라 대본에 억지로 맞추지 않습니다. 없는 손동작이나 상호작용도 새 자산 요구사항입니다.

1. `manifest.json`과 실제 컴포넌트를 확인해 그대로 쓸 것(`reuse`), 바꿔 쓸 것(`adapt`), 새로 만들 것(`create`)을 나눕니다.
2. 같은 역할은 같은 자산 ID를 사용하고 장면 ID·선택 이유·필요 동작을 연결합니다. 현재 사용자가 선택한 방식은 유형별 PNG 라이브러리이며 캐릭터/소품/리액션을 나눕니다. 예전 SVG를 PNG로 내보낸 경우 원본 경로를 기록하고, Dot이 준 새 이미지라고 혼동하지 않습니다. 향후 다른 방식은 새 요청과 레퍼런스에 따라 선택합니다.
3. `episodes/<id>/scene-plan.json`에 장면과 자산 계획을 저장합니다. 기획 단계의 대본 원본은 문서로 둘 수 있습니다. 아직 없는 음성 길이나 렌더 지원을 만들어내지 않습니다.
4. `node scripts/scene-assets.mjs --episode <id>`로 재사용 원본과 제작 예정 자산을 확인합니다. 이 명령은 계획과 파일 존재를 보고할 뿐 대본을 이해하거나 시각 품질을 승인하지 않습니다. 새 자산이 없다는 이유로 기획을 실패 처리하지 않습니다.
5. 제작 시 원본·파생 자산·모션을 연결하고 대표 포즈와 장면에서 확인합니다. 새 에피소드별 자산은 별도 폴더에 두고 기존 영상용 기본형을 무단 변경하지 않습니다.

자산은 역할별로 모으되, 장면에 맞을 때만 사용합니다. 기존에 있다는 이유로 서버·상자·웃는 얼굴을 모든 대사에 넣지 않습니다. 인물의 일관성과 표정의 적절성을 함께 확인합니다. 말하는 입이 실망 표정을 웃음으로 덮는 것처럼, 정지 포즈가 맞아도 영상에서는 달라질 수 있습니다.

대본 변경은 원본에서 시작해 음성·타이밍·SRT·공개 검토 데이터를 갱신합니다. 그림만 변경하면 기존 음성과 문장 구간을 유지합니다. 대표 프레임뿐 아니라 의미가 바뀌는 문장 경계의 전후도 봅니다.

중요 사실·대상·자산 누락·외부 공개 범위는 정확히 확인합니다. 미세한 시각 차이는 전체 인상과 가독성을 보고 판단하며 불필요한 승인/검사 단계를 늘리지 않습니다. 제작과 게시를 별도 행동으로 취급합니다.
