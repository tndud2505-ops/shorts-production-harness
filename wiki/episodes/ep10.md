# ep10 · 에이전트 만든다는데, 무슨 일을 줄이는 건가요?

상태: 사용자 고찰을 바탕으로 한 대본·연출 제안. 마지막의 “근데 문제는”은 추가 내용 없이 계속 진행하라는 확인을 받음. 약 90초를 목표로 압축하되 실제 길이는 낭독/TTS 전 미확정. 에피소드 번호는 별도 작업 중인 ep09를 보존하기 위해 분리했다.

이번에는 기존 영상의 피드백이 아니라 **새 시나리오 구성**이다. 원본 대본은 이 문서의 아래 초안이다. 아직 episode.json·음성·runtime·새 composition은 만들지 않았다. 다른 영상의 168.4초 타이밍을 복사하지 않는다.

## 핵심과 편집 판단

사용자는 ‘에이전트’라는 넓은 이름만으로는 실제 업무를 알 수 없고, 사람이 하던 어떤 작업과 판단을 맡기는지 정의해야 한다고 느낀다. 공통 처리, 전문성·취향에 따른 기준, 매번 상황에 따라 달라지는 판단을 구분한다. 실제로 만들고 검토·수정해본 업무 단위를 축적한 뒤 공용화하자는 주장이다.

‘에이전틱=판단을 포함한 자동화’는 사용자의 작업 관점으로 표현하며 공식 정의라고 주장하지 않는다. 세 범주는 서로 완전히 분리된 기술 분류라기보다 맡길 범위를 결정하는 관점이다. 상황 판단도 자동화가 절대 불가능하다고 단정하지 않고 검토·수정 비용이 커질 수 있다고 표현한다.

제안: 세 범주를 강의하듯 나열하지 않고 **한 편집 도구가 모든 영상에 똑같이 슬로모션을 적용하는 짧은 상황극**으로 차이를 먼저 보여준다. 상사의 인격이나 역량을 공격하는 대신 ‘업무 범위와 검증 없이 처음부터 공용화를 주문하는 과정’을 비판한다. 스포츠에서도 느린 화면이 항상 맞는 것은 아니고 예능에서도 코미디 효과로 쓸 수 있으므로, 아래 대사는 장르 자체가 아니라 **해당 순간의 의도**가 다름을 보여준다.

## 구어체 대본 초안

### 01-vague-request · 이름만 있는 주문

“영상 편집 에이전트 하나 만들어주세요.”

그런데… 어떤 편집이요?

저는 요즘 회사에서 ‘에이전트’라는 말을 들으면 이게 먼저 궁금해요. 개발 도구도, 챗봇도, 브라우저도 같은 이름으로 부르니까, 무슨 일을 맡기겠다는 건지 잘 안 보이거든요.

### 02-working-view · 맡길 일로 바꾸기

저는 사람이 하던 작업과 판단의 일부를 맡기는 자동화라고 생각해요. 그렇게 보면, 맡길 수 있는 범위도 나눠봐야 하죠.

### 03-same-button · 같은 버튼, 다른 결과

예를 들어 골 들어가는 순간은 천천히 다시 보고 싶을 수 있잖아요. 그런데 평범한 대화까지 전부 느리게 만들면… 답답하죠.

### 04-different-criteria · 무엇이 같고 다른가

말과 자막을 맞추는 일은 공통으로 묶기 좋아요. 자막 크기나 효과음은 영상 목적, 전문가의 판단, 취향이 섞이고요. 지금 느린 화면을 쓸지는 그 장면을 봐야 해요.

### 05-review-cost · 검토할 일은 남는다

이걸 한꺼번에 맡기면, 편집할 시간을 결과 고치는 데 쓸 수도 있어요. 만들어놓고 끝이 아니라, 원하는 결과가 나오는지 직접 써보고 계속 다듬어야 하거든요.

### 06-shared-criteria · 공용화보다 먼저 할 일

제가 답답한 건 그 과정은 건너뛰고, 처음부터 회사 전체가 쓸 걸 만들자는 거예요. 취향이 갈리는 부분은 개인 설정으로 두거나 팀에서 기준을 맞춰야죠.

### 07-small-scope · 작은 업무 단위부터

‘영상 편집을 자동화한다’보다 ‘매번 손으로 맞추는 자막 타이밍을 줄인다’부터요. 그렇게 실제로 쓰이는 것들을 하나씩 모아서 공용화하면 되고요.

### 08-close · 처음 질문으로 돌아오기

에이전트를 만들겠다는 말보다, 누가 하던 어떤 일을 줄일 건지부터 이야기했으면 좋겠어요.

## 장면 설계 제안

| 장면 | 보여줄 것 | 필요한 자산·동작 | 주의할 점 |
|---|---|---|---|
| 01 | ‘영상 편집 에이전트’라고만 적힌 요청 카드. 주인공이 빈 작업 범위를 가리킴 | 기존 설명/생각 포즈, 말풍선 + 요청 카드 변형 | 첫 주문은 설명용 상황극이며 실제 상사의 발언 인용이 아님. 상사 캐릭터는 불필요 |
| 02 | 큰 ‘에이전트’ 이름표 아래 실제 맡길 작은 일들이 드러남 | 작업 범위 카드, 기존 화살표·창 | SDK/MCP 설명은 생략. 실제 도구 사용법 강의로 새지 않음 |
| 03 | 간단한 골 재현과 평범한 대화가 같은 느리게 버튼에 연결됨. 대화에 적용한 뒤 바로 정상으로 복귀 | 신규 스포츠 미니 컷, 대화 미니 컷, 편집 속도 컨트롤, 주인공 반응 | 슬로모션 농담은 1회 짧게. 실제 음성 변속은 로컬 TTS 후 작업. 대화 내용은 설명용 예시 |
| 04 | 한 편집 화면에서 자막 싱크→크기/효과→장면별 선택을 순차 강조 | 신규 편집 타임라인, 스타일 옵션, 장면 선택 표시 | ‘공통/기준/맥락’은 시각적 보조. 긴 세 칸 표나 기술 분류 강의는 피함 |
| 05 | 자동 출력 파일이 검토·수정 경로로 되돌아옴 | 기존 파일·읽기 포즈 + 검토 루프 화살표 | 절감 시간·실패율·수정 횟수를 수치로 꾸미지 않음 |
| 06 | 처음부터 모든 사람에게 보내던 흐름을 개인 설정/팀 기준 확인으로 바꿈 | 요청 범위 도해 + 기존 창, 주인공 설명 | ‘상사는 아무것도 모른다’는 악역 연출 대신 절차의 문제 표현 |
| 07 | 자막 타이밍이라는 작은 작업 하나가 해결되고 재사용할 작업이 이어짐 | 같은 타임라인 재사용 + 작은 작업 연결 모션 | 서버/로봇 그림보다 실제 줄어드는 작업을 보여줌 |
| 08 | 처음의 막연한 요청 카드가 ‘누가 / 어떤 일 / 원하는 결과’로 바뀜 | 같은 요청 카드 재사용, 주인공 중립/설명 | 회사 전체 자동화 성공을 이미 이뤘다고 묘사하지 않음 |

기본 인물은 기존 주인공을 재사용하는 **제안**이다. ep08의 검정/아이보리 전체 레이아웃을 복사하도록 확정한 것은 아니다. Dot이 편집 화면을 중심으로 한 새 구도와 전환을 제안할 수 있다. ep09의 PNG 밈/도파민 연출도 자동 상속하지 않는다.

## 자산과 Dot 협업

구체적인 기존/변형/신규 목록: [scene-plan.json](../../episodes/ep10-agentic-scope/scene-plan.json). 보고 명령: `node scripts/scene-assets.mjs --episode ep10-agentic-scope`.

Codex: 의도·구어체·사실·자산 요구 정리, 사용자 피드백 반영, 확정 뒤 로컬 TTS·최종 결합. Dot: 같은 의미를 더 짧게 보여줄 구도 제안, 추가 자산/포즈 제작, 대표 장면 정지 이미지와 모션 시안. 신설 캐릭터는 대화 컷에 필요한 중립적인 상대 정도이며 상사 캐릭터나 별도 세계관은 만들 필요 없다.

초안 단계에서는 Dot이 이 문서에 의견을 제안하고 대본 원본을 동시에 수정하지 않는다. 전달 시 최신 Git 버전과 쓸 경로를 정한다. 아직 공개 저장소에 반영하지 않은 초안이다. 회사명·상사 이름·실제 대화 기록은 포함하지 않았다.
